# 미간프레스 홈페이지

miganpress.com의 소스입니다. 책과 문구는 구글 시트 **'미간프레스 웹사이트 데이터'**(드라이브 Migan Press 폴더)에서 관리하고, `build.py`가 그 시트를 읽어 `dist/` 폴더에 사이트를 만듭니다. 파이썬 표준 라이브러리만 써서 따로 설치할 것이 없어요.

## 페이지

| 주소 | 내용 |
|---|---|
| `/` | 다음에 나올 책 한 권과 미간에서 나올 책 |
| `/books/` | 책 목록(목록 보기 / 표지 보기) |
| `/books/주소/` | 책 상세 (시트의 '주소' 열이 그대로 주소가 돼요. 예: `miganpress.com/books/bibliophobia/`) |
| `/about/` | 소개, 연락처, 만드는 사람, 만든 책 |
| `/en/` | 해외 출판사·에이전시용 영문 소개 한 장 (머리의 지구본 아이콘) |

## 시트 구성

| 탭 | 내용 |
|---|---|
| 출간 도서 | 미간에서 낸 책과 낼 책. 한 줄에 한 권 |
| 편집한 책 (또는 만든 책) | 소개 페이지 '만든 책'에 표지로 보여 줄, 대표님이 만든 책 |
| 사이트 정보 | 아래 항목 이름을 A열에, 내용을 B열에 |

**사이트 정보 탭 항목:** 첫 화면 문장(검색·공유용 설명), 소개 큰 문장, 소개 문단, 영문 소개 문단, 대표 이름, 대표 소개, 대표 링크(한 줄에 하나씩 `이름 | 주소`, 대표 소개 아래에 새 창으로 열리는 링크로 나와요), 이메일, 찾아오시는 길, 인스타그램, 트위터(또는 X), 블루스카이. 이메일과 SNS는 비워 두면 연락처에서 빠지고, 찾아오시는 길을 비워 두면 '아직은 찾아오실 수 없습니다' 문구가 나와요. 영문 소개 문단을 비워 두면 기본 영문 소개가 나와요.

**출간 도서 탭:**

- **공개:** `N`으로 바꾸면 그 줄은 사이트에서 숨겨져요.
- **상태:** '출간 예정' 또는 '출간'을 골라요.
- **출간 연월:** `2027-03`처럼 적어요.
- **제목:** 줄을 바꾸고 싶은 자리에 `/`를 넣어요(예: `우리가 / 함께 읽는다면`). 브라우저 탭 제목처럼 한 줄인 곳에서는 띄어쓰기로 나와요.
- **지은이 · 옮긴이 · 저자명 원문 (여러 명):** 이름을 모두 쉼표로 나눠 적어요(예: `세라 치하야, 메르브 엠레, 캐서린 힐`). 사이트에서는 '세라 치하야·메르브 엠레·캐서린 힐'처럼 가운뎃점으로 이어지고, 세 명 이상이면 표지·책 목록·첫 화면에서는 '세라 치하야 외'로 줄어요. 책 상세에는 모두 나와요. 영문은 'A, B, and C'로, 영문 페이지 목록에서는 'A et al.'로 나와요.
- **원제 · 저자명 원문:** 책 상세 '원서' 줄에 '*Bibliophobia* by Sarah Chihaya'처럼 나와요(제목은 이탤릭). 원서 부제 칸은 사이트에 나오지 않아요. 원제와 저자명 원문은 영문 페이지 'Forthcoming titles'에도 쓰여요. 원제가 없는 책은 영문 페이지에 나오지 않아요.
- **태그라인 · 짧은 소개 · 책 소개:** 태그라인은 책 상세 맨 위에 굵게, 첫 화면 '다음 책' 옆에도 나와요. 짧은 소개는 책 상세 위쪽에 나오고, 긴 '책 소개'는 '책 소개 전체 읽기'를 눌러 펼쳐요. 하나만 있으면 그것만 보여요.
- **저자 소개 · 역자 소개 · 추천사:** 책 상세에 '지은이', '옮긴이', '추천의 말'로 나와요. 추천사는 한 칸에 여러 개를 빈 줄로 나눠 적고, 마지막 줄을 `— 이름, 직함`처럼 '—'로 시작하면 출처로 표시돼요.
- **수상 내역** (열 이름은 `수상 내역` 또는 `수상/선정 내역`)**:** 이 열을 만들고 한 줄에 하나씩 적어요(셀 안 줄바꿈은 Cmd+Enter / Ctrl+Enter). 책 상세에서 추천의 말 바로 다음 '수상 내역'으로 나오고, 왼쪽 목차에도 생겨요. 비워 두면 나오지 않아요.
- **차례:** 한 줄에 한 항목씩 적어요. 부(部) 사이에 빈 줄을 넣으면 조금 띄워져요. '차례 보기'를 눌러 펼치는 칸으로 나와요.
- **판형 · 사양 · 면수 · 정가 · ISBN · 부가기호:** `120*188`, `무선`, `320`, `18000`처럼 적으면 '120×188mm', '무선', '320면', '18,000원'으로 나와요. 부가기호는 ISBN 뒤에 붙어요. 비워 두면 그 줄은 나오지 않아요.
- **교보문고 · 예스24 · 알라딘:** 상품 페이지 주소를 넣으면 '구입처'에 링크가 생겨요. 출간 전에는 '출간 후 연결됩니다'가 나와요.
- **표지:** 비워 두면 글자 표지가 나와요. 이미지를 쓰려면 아래 '파일 넣기'를 보세요.
- **보도자료 · 표지 파일:** 링크를 넣으면 책 상세 정보칸 아래에 '관련 자료 받기'가 생겨요.

**공통:**

- **굵은 글씨:** 셀 안에서 원하는 부분만 굵게(Cmd+B / Ctrl+B) 하면 사이트에서도 굵게 나와요. `**이렇게**` 별표 두 개로 감싸도 돼요.
- **기울임:** 셀 안에서 원하는 부분만 기울이면(Cmd+I / Ctrl+I) 사이트에서도 기울어 나와요. `__이렇게__` 밑줄 두 개로 감싸도 돼요. 영문 책 제목 등에 쓰세요.
- **문단과 줄:** 문단 사이에 빈 줄을 넣으면 문단이 나뉘어요. 셀 안에서 줄을 바꾸려면 Cmd+Enter(맥) 또는 Ctrl+Enter를 눌러요.
- 탭 이름과 첫 줄 머리글은 바꾸지 마세요. 열 순서는 바꿔도 괜찮아요.

## 파일 넣기 (표지, 보도자료)

시트 칸에는 아래 셋 중 하나를 적을 수 있어요.

1. **구글 드라이브 공유 링크:** 파일을 '링크가 있는 모든 사용자: 뷰어'로 공유해야 해요. 표지는 사이트를 만들 때 사이트 안으로 복사되지만, 보도자료 링크는 드라이브를 그대로 가리키므로 드라이브에서 파일을 지우거나 공유를 끄면 받을 수 없어요.
2. **다른 이미지·파일 주소** (`https://…`): 그 주소를 그대로 써요.
3. **파일 이름만:** 표지는 `static/covers/`에, 보도자료 같은 받을 파일은 `static/files/`에 넣고 칸에는 파일 이름만 적어요. 사이트와 함께 배포되어 가장 오래 안정적으로 남아요.

만든 책 표지는 `static/covers/works/`에 있고, 제목과 파일의 짝은 `data/work_covers.json`, 분야(만화 등)는 `data/work_categories.json`에 적혀 있어요. 시트 '표지' 칸에 적은 것이 먼저 쓰여요.

## 시트를 고친 뒤

시트를 고쳐도 사이트는 저절로 바뀌지 않아요. 시트 메뉴에서 **미간 웹사이트 > 사이트 업데이트**를 눌러야 1~2분 뒤 반영돼요. 이 메뉴를 만드는 방법은 `apps-script.gs` 파일에 있어요.

## 처음 한 번만 하는 설정 (GitHub Pages)

1. **시트 공유:** '링크가 있는 모든 사용자: 뷰어'로 설정해요. 사이트에 공개되는 내용만 들어 있는 시트예요.
2. **저장소 만들기:** GitHub에 새 저장소를 만들고 이 폴더를 올려요(`dist/`는 올라가지 않아요).
3. **Pages 켜기:** 저장소의 Settings > Pages > Build and deployment > Source를 **GitHub Actions**로 해요.
4. **도메인 연결:** 같은 화면의 Custom domain에 `miganpress.com`을 넣고, 도메인 업체 DNS에서 GitHub이 알려 주는 대로 레코드를 추가해요. 연결이 끝나면 'Enforce HTTPS'를 켜요.
5. **배포:** `.github/workflows/deploy.yml`이 코드를 올릴 때와 수동으로 눌렀을 때 사이트를 다시 만들어 배포해요. 시간마다 자동으로 돌지는 않아요. 시트를 읽지 못하면 배포가 멈추고 기존 사이트가 그대로 남아요.
6. **시트의 '사이트 업데이트' 버튼:** 시트를 고친 뒤 이 버튼을 눌러야 사이트에 반영돼요. `apps-script.gs` 위쪽 설치 방법을 따라 하세요. 버튼 대신 저장소 Actions 탭 > Deploy site > Run workflow로도 같은 일을 할 수 있어요.

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `build.py` | 시트를 읽어 모든 페이지와 `sitemap.xml`, `robots.txt`를 만들어요 |
| `sheet.py` | 시트(xlsx)를 읽어요. 셀 안 굵은 글씨와 기울임도 살려요 |
| `static/style.css` | 사이트 모양 전부. 구역마다 휴대폰(720px 이하) 규칙을 바로 아래에 두었어요 |
| `static/favicon.svg`, `static/icons/` | 브라우저 탭 아이콘, SNS 공식 아이콘 |
| `partials/` | 로고(머리용 정지 로고, 소개용 움직이는 로고)와 작은 스크립트(눈 깜빡임, 이메일 보호) |
| `data/` | 만든 책 표지·분야 짝, 시험용 시트 사본(`sample.xlsx`) |
| `apps-script.gs` | 시트에 '사이트 업데이트' 메뉴를 붙이는 스크립트 |
| `.github/workflows/deploy.yml` | GitHub Pages 배포(푸시할 때, 수동 실행) |

이메일 주소는 수집 프로그램이 읽지 못하도록 페이지에 그대로 적지 않고, 페이지가 열릴 때 조립돼요.

## 직접 확인하기

```
python3 build.py                          # 시트에서 읽기
python3 build.py --local data/sample.xlsx # 내려받은 파일로 시험하기
python3 -m http.server -d dist 8000
```

시트를 읽지 못하면 빌드가 실패해요. 이때는 기존 사이트가 그대로 유지돼요.
